# MediTrack - Система мониторинга пациентов

Мобильное приложение для врачей, обеспечивающее мониторинг пациентов, управление консультациями и показателями жизнедеятельности.

## Бизнес-экраны (9 экранов)

### 1. Авторизация (Login Screen)
**Путь:** `/login`  
**Функциональность:**
- Вход в систему по email и паролю
- Валидация введённых данных
- Редирект на панель после успешного входа
- Переход к регистрации

### 2. Регистрация (Register Screen)
**Путь:** `/register`  
**Функциональность:**
- Регистрация нового врача
- Ввод персональных данных (ФИО)
- Выбор специализации
- Создание учётных данных (email, пароль)
- Валидация и подтверждение пароля

### 3. Панель мониторинга (Dashboard)
**Путь:** `/flow/v1`  
**Функциональность:**
- Общая статистика: количество пациентов, показателей, консультаций
- Статистика по статусам пациентов (стабильные, под наблюдением, критические)
- Быстрый доступ к процессу госпитализации
- Навигация к другим разделам

### 4. Список пациентов (Patients List)
**Путь:** `/flow/v2`  
**Функциональность:**
- Отображение всех пациентов
- Карточки с основной информацией (ФИО, диагноз, статус, палата)
- Поиск пациентов
- Переход к детальной карточке пациента

### 5. Карточка пациента (Patient Detail)
**Путь:** `/flow/v3`, `/patient/:id`  
**Функциональность:**
- Полная информация о пациенте
- История показателей жизнедеятельности
- Список назначенных лекарств
- Аллергии и противопоказания
- Информация о лечащем враче
- Редактирование данных пациента

### 6. Показатели жизнедеятельности (Vitals)
**Путь:** `/flow/v4`  
**Функциональность:**
- Выбор пациента для просмотра/добавления показателей
- Отображение: температура, пульс, давление, сатурация, глюкоза
- Добавление новых измерений
- История изменений показателей

### 7. Чат (Chat)
**Путь:** `/flow/v5`  
**Функциональность:**
- Внутренний чат для обсуждения пациентов
- Отправка и получение сообщений
- История переписки

### 8. Консультации (Consultations)
**Путь:** `/flow/v6`  
**Функциональность:**
- Список всех консультаций
- Добавление новых консультаций
- Привязка консультации к пациенту
- Редактирование заметок

### 9. Профиль врача (Profile)
**Путь:** `/flow/v7`  
**Функциональность:**
- Информация о текущем пользователе
- Образование и специализации
- Контактные данные
- Статистика работы (пациенты, консультации)
- Редактирование профиля
- Выход из системы

## Горизонтальный Flow: Процесс госпитализации

Пошаговый мастер для госпитализации нового пациента:

1. **H1 - Триаж и AI-справка** (`/flow/h1`)
   - AI-ассистент для первичной оценки симптомов
   - Поиск информации о заболеваниях

2. **H2 - Регистрация пациента** (`/flow/h2`)
   - Ввод данных нового пациента
   - Назначение палаты и лечащего врача

3. **H3 - Первичные показатели** (`/flow/h3`)
   - Запись первичных vitals
   - Температура, давление, пульс и др.

4. **H4 - Первичная консультация** (`/flow/h4`)
   - Оформление первичного осмотра
   - Заметки и рекомендации

5. **H5 - Итог госпитализации** (`/flow/h5`)
   - Сводка по новому пациенту
   - Подтверждение данных

## Архитектура и State Management

### Выбор: MobX

**Обоснование выбора MobX:**

1. **Много бизнес-логики:** 
   - Управление пациентами (CRUD операции)
   - Связь между сущностями (пациент → vitals, пациент → консультации)
   - Контекст госпитализации (текущий пациент в процессе)

2. **Централизованный Store:**
   - `AppState` - основное хранилище данных приложения
   - `AuthState` - состояние авторизации
   - Все сущности взаимосвязаны и требуют синхронизации

3. **Реактивность через декораторы:**
   - `@observable` - реактивные данные
   - `@computed` - вычисляемые свойства
   - `@action` - мутации состояния
   - `Observer` widget - автоматическое обновление UI

4. **Почему не Riverpod/Bloc:**
   - **Riverpod**: Хорош для малого количества данных и простой реактивности, но у нас много связанной бизнес-логики
   - **Bloc**: Подходит для event-driven архитектуры, но избыточен для данного приложения
   - **MobX**: Оптимален для централизованного store с взаимосвязанными сущностями

### Структура State Management

```
lib/
├── shared/
│   ├── state/
│   │   ├── app_state.dart      # Главный store (пациенты, vitals, консультации)
│   │   └── app_scope.dart      # InheritedWidget для доступа к store
│   └── di/
│       └── locator.dart        # Dependency Injection (get_it)
│
├── features/
│   ├── auth/
│   │   └── state/
│   │       └── auth_state.dart # Store авторизации
│   ├── chat/
│   │   └── state/
│   │       └── chat_state.dart # Store чата
│   └── ...
```

### Принципы работы с данными

1. **Единый источник истины:** Все данные хранятся в `AppState`
2. **Реактивное обновление:** Изменения автоматически отражаются в UI через `Observer`
3. **Действия через @action:** Все мутации явные и отслеживаемые
4. **Вычисляемые свойства:** Производные данные через `@computed`
